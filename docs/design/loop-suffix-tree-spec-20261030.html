Loop 后缀树投机解码

2026-10-30 讨论稿 · 借鉴 SuffixDecoding（arXiv 2411.04975）· 不训练任何组件 · 输出与逐词贪心解码相同

在一棵草稿树里同时用两种猜词来源。后缀树不占块调用，一次就能续写好几个词；loop 的浅层读出每猜一个词要花 d 次块调用。前者负责续写，后者负责在跑满 T 层之前检查后缀树给的分支，剪掉错枝、补上漏掉的词。最后只提交与全深度读出一致的词。

一步解码怎么走

已提交的上文记作 x1:n，最后一个词 xn 还没跑过 loop。T 是全深度循环次数，d 是读草稿用的浅层深度。

  1. 起草（0 次块调用）。后缀树按原方法起草：取最长匹配，草稿长度上限为 α·p（p 是匹配长度），按出现频率打分，生成一棵候选树。分数够高就直接用。分数不够时，先等 xn 跑到深度 d，用它的浅层读出当第一个草稿词，再让后缀树从这个词往后续写。
  2. 深度 d 检查与补位（d 次块调用）。所有候选节点一起跑 d 层，每个节点在深度 d 的读出就是对它下一个词的浅层猜测。
    • 不在读出前 m 名里的子分支，剪掉。
    • 读出给出的词不在树上，就补成新节点。新节点晚 d 次调用才开始跑，开始后同样可以让后缀树从它往后续写。
  3. 深度 T 核对（再跑 T − d 次）。留下的节点继续跑到深度 T。沿树找出与全深度读出逐词一致的最长路径，接受这条路径，再加一个奖励词，即最后一个被接受节点的全深度读出。前 d 层的计算直接沿用，不重算。
上文或全深度给出的词 浅层读出给的草稿 后缀树给的草稿 在深度 d 读出 被剪掉 全深度核对通过

为什么两种来源能互补

loop 浅层读出后缀树
代价每猜一个词 d 次块调用，只能一个接一个0 次块调用，在 CPU 上算，一次给出多个词
擅长任何文本，平均来说较准重复内容：本题上文和以往输出里出现过的片段
自带的信心读出概率匹配长度和频率分数
在本方案中的作用给第一个词；检查后缀树的分支；补上漏掉的词续写多个词；在浅层最可能的词之外提供候选

在普通模型上，SuffixDecoding 每一步要在后缀树和 EAGLE-3 之间二选一，因为一次只核对得起一种草稿。在 loop 里，浅层读出本来就是核对计算的前 d 层，用它检查后缀树几乎不花额外的块调用。两种来源可以放进同一棵树，不必轮流用。

成本怎么算

  • 逐词解码：每个词 T 次块调用。
  • 只用浅层串 k 个草稿：每步 k·d + T 次，最多产出 k + 1 个词。
  • 本方案：每步基本是 T 次。第一个词要等浅层读出时多 d 次，有补位时再多 d 次（补位可以继续套用）。
  • 行数：所有候选节点只跑前 d 层，跑满 T 层的只有留下的节点。所以草稿树放长，多出的主要是前 d 层的行数。

主指标是每个输出词花的块调用次数，同时报告平均接受长度和“行数 × 调用次数”（算力）。只提交与全深度贪心读出一致的词，所以输出不变；bf16 数值误差另行统计。

离线怎么测

  • 框架：用 ArcticInference 的 suffix_decoding/simulator.py 离线回放，不经过 vLLM。在它的核对环节加两样：深度 d 的检查与补位，以及块调用的计数。
  • loop 模型要提供：全深度贪心输出 y，以及沿 y 在各个深度做 teacher forcing 得到的读出（取前 m 名）。前文正确时，深度 d 的读出与解码时看到的一样，所以正确路径上的剪枝、补位和接受都能精确算出。错误分支的行数按上界计。
  • 对照：逐词全深度；只用浅层串草稿；只用后缀树（原方法，全深度核对）；后缀树加浅层（本方案）。
  • 模型：Ouro-2.6B（T = 4）和 Huginn-0125（T = 32），版本与现有批次一致。
  • 待定：用哪些输入（开放式还是重复型），以及和 loop-spec-reuse-20261030 批次的关系。
