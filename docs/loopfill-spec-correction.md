## 假设

1. top-8过度扩展；top-1/2会损失部分覆盖，但能大幅降低循环行、读出行和替换成本。
2. 对每个新模型孩子立即查询后缀会扩大低价值子树；限制续查数量可能更划算。
3. N是容量上限，不应驱使零分路径占满预算。只排除零路径分数，可以独立检验该问题，不把它混同于校准准确率。
4. 即使保留相同生成规则，更小N也可能提高吞吐；这是容量消融，不能单独证明排序更准确。
5. shallow-only对照可以区分模型树本身成本与融合后缀的增量收益。

## 统一节点预算对照 接在当前Q队列之后

| 方法 | 逻辑预算含义 | 处理 |
| --- | --- | --- |
| AR | 无草稿，N=0 | 保留已有完整baseline，不按N重复 |
| 原生WFD | `max_draft`控制路径深度，不是物理槽数；T=32、d=4、top1单链流水最多8个未完成节点含根 | 已有480题max_rows峰值也是8；由先出生祖先先完成、每d轮只延伸一词的单链结构，未确认草稿不超过7，因此N≥8不改变这条流水；保留原生结果，不伪造四个不同N结果 |
| 原生LoopSpec | d1=4、d2=8控制双提案流水，没有通用N参数 | 保留原生结果；109是物理临时槽位上界，不能解释成N=109。已有运行推进峰值50含根，也不是扩展瞬间总驻留数 |
| LoopSpec-capped | 根以外所有未接受节点不超过N | 新增明确命名的受限变体，不能当作未改动的原生LoopSpec |
| budget-shallow | 相同N，仅模型top2 | 统一循环树计数，关闭后缀 |
| budget-suffix | 相同N，仅后缀Q4 | 统一循环树计数，关闭浅层提案 |
| budget-raw | 相同N，模型top2与后缀Q4共享 | 完整融合方法 |

四种带预算方法统一约束已分配循环树/KV槽的未接受草稿，不计已确认根，计入算完但尚未接受的草稿。budget方法在CPU上生成、尚未入选分配槽的候选不计入N，其检索和排序开销仍计入墙钟时间；因此等N不意味着等候选数或等FLOPs。预算版物理槽为N+1；LoopSpec-capped为`min(N+1, 原生所需物理槽数)`。未确认祖先必须保留，所有输出仍由全深度验证决定。原生AR/WFD/LoopSpec保持各自正确运行需要的缓存分配，不把WFD的1152个追加式物理槽强行缩成N+1，否则会混入缓存触顶和调度改变。

LoopSpec-capped保留原生d1/d2读出与推进顺序；按原生d1提案、再d2提案的顺序接纳新节点，满N时拒绝新提案，保留已有路径，不做概率排序或替换。根永不受限。记录`budget_rejections`与包括扩展瞬间在内的`peak_draft_nodes`。这会改变原生候选集合，可能特别影响第二提案，属于明确的资源约束消融，不声称与原论文调度完全相同。非绑定预算的测试要求循环调用与计算行数和原生相同。

总计 **16个比较单元，新增13组**：当前Q矩阵中GPU3上的raw-top2 Q4、shallow-top2、suffix Q4提供三个N64控制。预算解码器、batch执行器和packed后端不变；新增源码只扩展LoopSpec-capped及CLI分支，保留来源路径和复用审计。新LoopSpec-capped的N64仍需实际测量。

| GPU | 等待当前Q队列自然结束后的任务 |
| --- | --- |
| 3 | N8四臂 → 复用N64三臂 → N64 LoopSpec-capped |
| 6 | N16四臂 |
| 7 | N32四臂 |

同N四臂固定同一卡；跨N涉及不同卡，统一设备型号、频率、CPU亲和性政策并记录物理UUID。既有AR/WFD/原生LoopSpec作为额外吞吐锚点，不对微小跨卡差异做显著性结论。没有新增模型、batch或重复。各卡使用独占文件锁等待当前Q队列释放；不停止当前实验，不修改其冻结源码或baseline队列。

主要指标为整流实际输出token数除以墙钟时间，以及完整480题总时间。与同模型/B/卡的AR、WFD、LoopSpec、纯后缀比较；新增变体优先对新raw控制组比较。输出长度与BF16逐词一致率同时报告，不剔除分歧题。

## 后续阶段

### 后缀提案数量与收益成本关系

2026-11-04讨论补充。原32组只改变模型宽度、续查频率和驻留预算，没有独立改变每次后缀查询的提案上限，因而不能识别后缀提案数量的最优点。下方推导是新Q实验的依据；完整五档Q的设想由文档开头的单模型三档11组方案收敛执行，不额外启动原32组或五档全矩阵。

区分四个量：`k`是每个浅层读出的模型候选宽度；`Q`是每次后缀检索返回的树节点上限；`N`是每请求未接受节点的驻留上限；`m`是某一条后缀链的深度。Q不等于m，多次查询可累计很多候选，N也不等于每轮实际计算量。

当前ArcticInference接口还按`factor × match_length + offset`限制返回量，本轮factor=1、offset=0、min_token_prob=.001。因此把Q从32增到64未必增加任何候选；必须记录匹配长度、实际返回数、入选数和推进数，不能只看配置值。`Q=0`不能作为无后缀对照：库的0有特殊语义且本地配置要求正数；无后缀应显式使用`budget-shallow`。

#### 链式理想模型

固定一个已确认上下文。设浅层提出的第一词等于全深度贪心词的概率为p；第j个后缀词在前面浅层词及后缀词全部正确时，条件命中概率为a_j。后缀第j词被接受的概率为：

\[
P_j=p\prod_{i=1}^{j}a_i.
\]

假设整条草稿链都已完成验证，每轮有一个全深度fallback/bonus token，且暂不考虑EOS和长度上限，则浅层第一词加m个后缀词产生的期望总输出为：

\[
L_m=1+p\left(1+\sum_{j=1}^{m}\prod_{i=1}^{j}a_i\right).
\]

若把所有条件命中率近似成常数a（0≤a<1），则：

\[
L_m=1+p\frac{1-a^{m+1}}{1-a},\qquad L_{m+1}-L_m=pa^{m+1}.
\]

这是条件概率链式展开，不要求各位置在未经条件化时独立；用一个总体平均接收率代替所有a_j则是强近似。p、a_j都指真实验证命中事件，不能直接拿浅层softmax或检索频次充当这些概率。只有纯后缀、没有浅层前置词时，公式改为`1+Σ_{j=1}^m Π_{i=1}^j a_i`。

令C_m为这个决策窗口的期望实际耗时，长期速率近似为L_m/C_m。增加一个后缀词有利的充要比较为：

\[
\Delta L_m\,C_m>L_m\,\Delta C_m.
\]

当新增成本为正时，即`ΔL/ΔC > L/C`；相同命中率在不同硬件/B/Graph状态下可以有不同最优长度。如果成本恒定且a>0，L随长度增长，未必存在有限的内部最优点；实际有限最优来自成本上升、容量或时序限制。不能声称仅知道两个平均接收率就能解出一个通用最佳Q。

示意计算（非本实验测量）：p=a=.8、C_m=1+c·m，在m=0…64中枚举；c=.02时m*=10，c=.10时m*=4。相同准确率、不同边际成本，最优长度明显不同。

经典链式speculative decoding也以期望接受长度除以draft+verify成本选择草稿长度，见[Leviathan等，2023，§3.5](https://proceedings.mlr.press/v202/leviathan23a/leviathan23a.pdf)。上述浅层接后缀的展开为本实验的简化建模，不是该文直接给出的LoopFill结论。

#### 树与循环推进的修正

对一棵固定、去重、祖先闭包且所有节点已可验证的贪心草稿树，节点v的整条路径命中概率记为P_v，则理想期望输出为`1+Σ_v P_v`。同一条token路径即使由两种来源提出也只算一次。P_v沿路径展开为条件概率的乘积；不能将共享祖先的各边当作无条件独立事件。硬件相关树大小/深度优化可参考[Sequoia §4.1](https://arxiv.org/html/2402.12374v3)。

同一父节点上，模型候选集合M与后缀候选集合S的下一词覆盖率是`P(M∪S)=P(M)+P(S)-P(M∩S)`。两来源通常相关；必须测交集，不能假设独立，也不能把日志中初次入树的origin计数当成交集。共同提出同一词可能帮助判断可信度，但不会产生两份接受收益。

LoopFill在不同loop深度交错推进，不满足每轮所有节点已验证的理想条件。部分计算也能节省后续时间；另一方面，晚到的高命中候选可能几乎没有提前量。因此最终目标应计入候选在真正需要时已完成多少循环、依赖祖先何时可用、加入候选带来的新增批次耗时。上述长度公式用于解释趋势，不能直接预测当前wall_s，也不能把accepted_lengths不同调度器间直接等同。

#### 五档探索设想 当前先执行三档

优先在两个模型B=8、N=64固定时比较`Q∈{4,8,16,32,64}`，分别对纯后缀、raw-top1、raw-top2测曲线。factor、offset、检索概率门槛、题序、输入480条和其余执行设置固定；无后缀的top1/top2另作对照。Q=64的已有结果仅在源码、统计开销及协议一致时复用，否则补控制组。先识别Q效应，再增加Q×N的联合实验；不一开始混改多个参数。

每个Q记录实际返回节点数分布、匹配长度、树宽/深、来源重叠、正确路径分深度存活率、进入GPU的节点数、节点被接受时已完成loop数、浪费rows/token、查询/读出成本和总吞吐。细粒度路径轨迹放独立诊断流，不混入正式测速。

同一N下Q变大可能挤掉模型候选，也可能改变本地/全局检索结果的选择，不保证树嵌套或最终覆盖单调增长。除Q的曲线外，检查max_spec_factor限制是否经常先触发；若是，再单独登记factor消融。最终以实测吞吐和质量报告每个点，不把本480题上选出的最优点包装成独立确认结果。

第一阶段完成后，以结果决定是否值得实现更复杂策略，不自动启动：

- 用已确认父路径上的全深度argmax作为反馈，按读出深度、排名、分差、两次读出一致性和来源一致性估计命中率。仅记录提出时的特征，不把未来验证信息泄漏进选择；缺失和未验证路径单独处理。
- 引入预计接受收益与新增批次耗时的比较；预算约束计算成本，而不仅是节点数。成本需要独立微基准或profile，不能从现有计数杜撰。
- 将轻量候选保留与GPU继续推进分开，保护根的进度，并满足祖先逐层KV依赖。暂停与恢复必须另做正确性测试。
- 若排序变化仍无法改善吞吐，再单独比较Graph覆盖策略及算子开销；不把后端优化与候选策略混成同一个消融。

任何后续选择后的全量结果都仍属于开发数据结果；正式确认需要额外题序/重复或独立数据，按后续明确范围执行。
