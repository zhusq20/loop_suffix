## 1. 中心论点

后缀检索与早期循环预测具有互补性。在同一棵草稿树内接续两种来源，可以更早启动未来正确位置的计算，并在有限节点预算内减少生成所需的串行 loop steps。

证据组织：**主实验展示性能；机制分析解释互补、提前计算及计算效率；四维消融验证关键设计。** Online 权重是附加改进，其重要性由实测收益决定。

## 2. 两个主指标

- **Throughput**：实际输出 token 数 / 请求流墙钟时间；明确是否包含 prefill，沿用对应计时协议。
- **循环归一化平均接受长度（Normalized Mean Accepted Length，γ）**：每 T 个 loop steps 平均生成的 token 数。

对请求 i：`γ_i = T × L_i / C_i`。任务或同模型整体汇总：`γ = T × ΣL_i / ΣC_i`。

| 符号 | 定义与代码口径 |
| --- | --- |
| T | 完整循环深度：Ouro 为 4，Huginn 为 32 |
| L_i | Prefill 后生成的 token 数，含纠正/补出 token；取 `stats.tokens`，排除 prefill 直接产生的首 token |
| C_i | 逐请求 decode loop steps；取 `stats.calls`，计入没有提交 token 的推进步骤 |

一个请求的所有活跃节点并行各推进一轮 recurrent block，记 **1 个 loop step**；10 个节点一起推进一轮是 1 step、10 node-loops（rows）。Batch 下仍逐请求计数，不用 GPU 合并后的 `core_calls` 作分母；不使用含义不统一的 `stats.steps` 或 `accepted_lengths` 替代。只有 prefill 输出、L_i=C_i=0 的请求不定义 γ_i，保留请求并报告数量。

AR 的 γ=1。若每次目标验证恰好执行 T 轮循环，则 γ 退化为每次验证的平均输出长度。流水线方法使用实际 loop steps，包含启动和终止边界，不直接套用 LoopSpec 的提案来源加权公式。γ 衡量串行步骤节省，不等于墙钟加速，也不衡量总计算量。

## 3. 主实验

- 模型：Huginn-3.5B、Ouro-2.6B；当前正在执行的 Huginn throughput 实验按原协议完成。
- 方法：AR、同引擎 WFD、同引擎 LoopSpec、Suffix-only、LoopFill-raw、LoopFill-online。
- 数据：Spec-Bench 480 题；六类为 MT-Bench、Translation、Summarization、QA、Math Reasoning、RAG。MT-Bench 的八个子类合并为 80 题。
- 展示：吞吐随 B 的曲线，以及各任务/各方法的 γ；同一模型、B、输入、历史与后端协议内比较。
- γ 先从已有逐请求日志提取，不为该指标重跑计时。可按类别汇总 γ，但不能把混合流墙钟分摊成类别吞吐。

### 4.1 读出位置 × Top-k：六组核心对照

动机来自[图一结果](loopfill-preliminary-plan.md#正式结果480题)：Ouro-2.6B、greedy、top-1 的 loop 1/2/3 单层命中率分别为88.83%/95.63%/98.20%，第2/3轮新增覆盖为7.89/2.23个百分点。第一轮已经覆盖大部分位置，但单层命中率并非最高。待检验的假设是：更早增加候选能否替代较晚读出的补充，并降低实际解码开销。图一的候选覆盖不能直接证明执行收益，也不能直接外推到 Huginn 或 temperature=1。

以 d₁/d₂ 表示模型的两处浅层读出：Ouro 为 loop 1/2，Huginn 为 loop 4/8。下表“仅首次”对 Huginn 指仅 loop 4，不改为物理 loop 1；全深度验证始终保留。

| 配置 | 浅层读出位置 | 每个位置每次读出的候选数 | Suffix 接续 |
| --- | --- | --- | --- |
| 首次 Top-1 | 仅 d₁ | 1 | 完整接续 |
| 首次 Top-2 | 仅 d₁ | 2 | 完整接续 |
| 首次 Top-4 | 仅 d₁ | 4 | 完整接续 |
| 双次 Top-1 | d₁、d₂ | 各1 | 完整接续 |
| 双次 Top-2 | d₁、d₂ | 各2 | 完整接续；与母配置共用 |
| 双次 Top-4 | d₁、d₂ | 各4 | 完整接续 |

关键比较：

- 固定读出位置，比较 Top-1/2/4：单候选是否足够，增加低排名分支是否增加覆盖，或挤占正确路径预算。
- 固定 Top-k 比较仅 d₁ 与 d₁+d₂：第二次读出在不同候选宽度下仍有多少价值。
- 首次 Top-2 对双次 Top-1、首次 Top-4 对双次 Top-2：更多候选提前提出，与分两次提出候选的实际收益如何。不能将两者称为等计算量或等唯一候选数。

六组统一 N=16，根部 suffix 查询上限 Q=4，每个模型孩子的查询上限均为4（随 k 分别为 (4)、(4,4)、(4,4,4,4)），保持母配置的 online 权重控制规则、初值和逐请求重置方式。固定输入、题序、模型、B、生成/采样与历史协议、后端；具体执行协议在启动前冻结，greedy 与 temperature=1 不混合汇总。Top-1 空出的预算允许正常后续扩展，不人为填满，也不同时增大总预算 N。

Top-k 表示同一位置的候选分支数，不表示连续 draft k 个 token。相同 N/Q 不保证相同实际节点数、查询次数或计算量。较深读出还会更新已有候选分数，关闭 d₂ 同时影响候选补充与排序；本矩阵衡量其整体作用，不能将差值全部归因于新候选。

### 4.2 Suffix 接续预算：四组展示，仅新增两组

Q 表示一次 suffix 查询最多返回的候选树节点数，不是查询次数，也不等于单条连续续写长度。本面板固定根部 Q=4、N=16、Top-2以及母配置的权重控制规则，只改变读出位置和每个模型孩子的查询上限。

| 配置 | 浅层读出位置 | 孩子查询上限 | 复用关系 |
| --- | --- | --- | --- |
| 首次 Top-2，Q4 | 仅 d₁ | (4,4) | 复用 (b) |
| 双次 Top-2，Q4 | d₁、d₂ | (4,4) | 复用 (b)，即母配置 |
| 首次 Top-2，Q8 | 仅 d₁ | (8,8) | 新增 |
| 双次 Top-2，Q8 | d₁、d₂ | (8,8) | 新增 |

(b)/(c) 合计8个唯一配置。比较各读出方案从 Q4 到 Q8 的变化，以及同一 Q 下两种读出方案的差距。固定 N 时，更多返回候选仍受预算竞争，不能预设最终 γ 单调提高。本轮只检验 Top-2 下的 Q 敏感性，不扩成 Top-k × Q 全交叉矩阵，不加 Q=2 或根部 Q 扫描。

### 4.3 指标与实验规模

核心报告 γ、loop steps/token、rows/token、readout rows/token、实际节点占用、suffix 查询次数和丢弃分支计算。候选覆盖之外，检查节点成为根时已完成的循环数，以判断更早提案是否转化为提前计算。关键读出配置同时记录正常执行的实际吞吐；诊断 trace 单独采集，不混入计时。不恢复全矩阵重复计时，不用更高 γ 直接推断更高吞吐。

四面板复用母配置及重合单元：读出配置6组 + 接续预算新增2组 + 节点预算新增3组（N=8/32/64）+ 固定权重新增3组（c=0.5/0.7/1），因此**每个模型/B 共14个核心唯一配置**。Huginn-3.5B与Ouro-2.6B的B16共28组；用户确认额外测两模型/B1节点预算，共8组，总计36组。审计通过的4个母配置复用，新增32组，不扩成所有batch或新增模型矩阵。

Top-1 是核心对照。权重面板保留上述四组，不扩展初值/学习率扫描，也不与读出或 Q 矩阵交叉；来源开关对照不在本轮执行范围内。

## 5. 主实验之外的机制分析

| 分析 | 实验与统计 | 图表/论点 |
| --- | --- | --- |
| 来源互补 | 在相同已验证前缀、历史和候选上限下，统计两源都命中、仅模型命中、仅 suffix 命中、均未命中；补两种条件补救率 | 分任务堆叠柱状图；解释为什么融合 |
| 提前计算 | 在保留的读出/Q配置中记录接受路径的来源切换、接续后接受长度，以及节点成为根时已完成的循环数 | 来源分解 + 已完成循环数 CDF；解释不同读出时机与接续预算下的提前计算 |
| 计算效率 | 复用 N、读出和Q消融的 loop steps/token、rows/token、丢弃分支计算，不新增纯模型/纯suffix来源消融 | 计算量—串行步骤曲线；解释额外计算是否值得 |
| 适用条件 | 在固定参考前缀上按 suffix 可用性、early-loop 命中能力分组，观察接续频率与 loop-step 收益 | 热图/分箱曲线；解释何时最有效 |

同一节点由多个来源提出时不重复归功，记录首次引入与后续重合标记。真实轨迹例子只作解释，整体分布支撑结论；离线候选覆盖不冒充实际执行收益。机制分析优先共用分层请求和 trace，先检查已有日志，再补缺失字段。

## 6. 附加分析与执行顺序

- 若正文强调 online：补请求内 c、suffix 成功情况及预算占用的轨迹；控制器逐请求重置，不用跨请求变化证明权重适应。
- 历史积累/二轮、上下文长度和运行开销分析按论文论点需要补充，不默认扩成全量矩阵。
- 顺序：**汇总现有 throughput 与 γ、核对可复用配置 → 六组读出矩阵及两组Q8补充 → 节点预算/权重消融 → 来源互补/提前计算/计算效率 → 适用条件及必要附录**。
- 当前规划不安排正确性诊断、任务质量评分和官方原生基线直接对照。既有数值分歧和实现边界如实保留，本文不将其视为已解决。
- 冻结正式配置；披露 Spec-Bench 已参与选参，不称独立留出确认。不重新启动已撤销的重复计时；历史计时仅在协议匹配时复用，Graph-on/off 分开。
- 同步论文方法节到节点预算与在线权重版本；旧离线校准/阈值结果仅作历史或附录。
- 保存输入/配置/源码标识和逐请求计数。Git 提交文档、代码、测试、轻量配置；完整输出、trace、重复源码快照、缓存及权重留在本地 `results/` 等目录。
