# LoopFill 草稿树：每请求节点预算定稿

2026-11-04，v4。**已采用每个 request 的未接受草稿树节点预算 N，替代固定路径分数阈值 τ。** 新增 [预算解码器](../src/llm_memory_editability/loop_budget_decode.py) 和 raw/online/suffix 三个入口；尚未完成全尺寸评测。旧 v3 阈值实现保留。最新一轮的统一 N、无需校准数据方案见 [在线控制器第11节](loopfill-online-suffix-control.md#11-已实现接口与下一轮比较方案)，下文开发网格是原设计记录，不再是本轮启动的前置要求。

## 预算计数

- 每个请求独立满足 `未验证草稿节点数 ≤ N`，N 是上限，不要求填满。不跨请求借用名额；请求并发数记为 B。
- prompt、已确认前缀和当前已确认根不计入 N。根必须继续完成计算，不参与候选淘汰。
- 所有尚未被接受的草稿节点计入 N，包括已完成全部 loop、但仍在等待前缀验证的节点。全深度计算完成不等于 token 已被接受。
- 同一父节点下相同 token 合并为一个节点；相同 token 在不同路径上分别计数。
- 历史 suffix tree 是检索索引，不计入 N。已确认但尚未 flush 的 KV、根和临时工作区另外计入物理显存，不能把 N 直接当作缓存槽数。

## 分数排序与容量选择

神经候选保留早期全词表 softmax 的 top-8 值，后缀候选保留检索条件边分数。raw 只表示未做离线校准的评分方式；普通 Loop Transformer 基线叫 AR。新读出替换旧边分数，沿相对当前已确认根的路径计算 `S(v)=S(parent)×e(parent→v)`，根分数为 1。分数是排序启发式，不声称是真实接受概率。

**取消草稿树固定 τ 入场与 τ 剪枝。** 候选不足 N 时可少于 N；分数为零本身不触发阈值淘汰。候选提案仍是有限的：每次模型读出最多 8 个 token，每次后缀查询最多 64 个 token。检索器自身的候选生成设置单独记录，不能把“取消草稿树 τ”写成“所有模块都没有任何阈值”。

每次选择在现有未验证节点和本轮已生成候选的并集上进行，按 S 从高到低保留至多 N 个，且必须保持祖先闭包：保留节点时，其未验证祖先也必须保留。分数相同先选距离当前根更近的节点，再按根到节点的 token ID 路径字典序确定顺序。边分数在 [0,1] 内时，这个排序保证祖先先于后代。它是当前可见候选池上的选择，不是对尚未生成的全部续写求全局最优。

满额后新高分候选可以替换已有低分节点，不采用“先到先得、满了直接拒绝后续候选”。被淘汰节点的后代一并失效；保留节点复用已有状态，被淘汰状态不能在之后重新入树时当成有效缓存。新候选先以轻量元数据参与选择，入选后才分配模型状态；每次扩展/重评分事件处理完成、下一次模型调用前，都应满足预算。

## 验证、补位与循环推进

1. 当前已确认根推进到全深度，只有它的全深度预测决定下一个输出 token。
2. 若该 token 在草稿树内，接受它，删除不匹配分支，将它设为新根并移出 N 的计数；其后代分数相对新根重新计算。若其全深度结果也已就绪，可以继续接受。
3. 若目标 token 不在树内，仍提交目标 token，建立新的已确认根；不能为了满足预算或复用候选而改变目标输出。
4. 接受后更新本题可见历史，并从新前沿补充候选；新入选的模型孩子继续支持后缀续查。每次补充均执行同一预算选择。
5. 保留节点中所有尚未完成 loop 的节点照常推进，保证祖先状态可用。不另引入“每轮只挑 K 个、其余暂停”的调度器。按上述计数，当前根加未完成草稿最多 N+1 个推进节点；已完成但未接受节点仍占 N，但不再执行 loop。

保持现有历史隔离：未验证候选可以用于查询上下文，不能写入历史索引；跨请求历史只在请求完成后发布。算法提交规则和有限精度实现的一致性分开验证，现有 Ouro BF16 分歧仍需定位。

## 参数、命名与验证

- 新结果显式登记 `tree_policy=node_budget`、`scoring=raw` 和 `draft_node_budget=N`；CLI 已支持 `--draft-node-budget` 和 `budget-*` 臂。旧结果保持原名并标识其 threshold 策略，不能把旧 `--max-nodes` 当作 N。
- 先以 N=64 作为开发起点；开发网格固定为 16/32/64/128/256。按模型/B 在独立开发数据上选择，吞吐相差不超过最优 1% 时取更小 N，正式评测前冻结，跨任务沿用。64 尚不是已测最优或正式冻结值。
- 原型必须检查：N=0 的无草稿回退、N=1、祖先闭包、同分顺序、满额替换、重评分、接受后重新计数/补位、算完但未接受仍占预算、EOS、缓存回收和请求隔离；检查目标输出规则与 AR 对齐。
- 记录未验证节点峰值、实际推进 rows、预算淘汰/拒绝数、接受长度、后缀查询成本、显存和吞吐。旧 `cap_skips` 仅表示物理容量问题，不能混作预算淘汰。

## 文献依据

## 历史：v3 阈值实现说明

以下为 v3 阈值实现；四表为 legacy 对照，见 [实验计划](loopfill-icml-experiments.md)。本文对应实际 [评分器](../src/llm_memory_editability/loop_score_ablation.py) 与 [解码器](../src/llm_memory_editability/loop_prob_decode.py)，不改变已有运行的实现。

### 每条边只保存一个当前分数

| 候选来源 | raw 边分数 e | 不使用的特征 |
| --- | --- | --- |
| 模型的早期读出 | 全词表 softmax 中该 token 的值，只提出 top-8 | 不按 rank、是否来自后缀等条件查表；top-8 不重新归一化 |
| 后缀检索 | 检索器返回的条件边分数 q | 不按匹配长度、竞争分支、提前深度查表 |
| 较深一轮模型读出 | 用这次 softmax 替换已有边分数 | 不把两次读出相乘，也不查 joint 表 |

后缀 API 返回路径分数时，用孩子路径分数除以父路径分数恢复条件边分数，见 `_edge_probs`。本地 prompt/已验证输出与已完成请求历史分别查询，取 draft.score 更大的整份草稿（平局取本地）；不会把两个来源的证据相加。检索分数依赖在线历史，raw 不等于完全不依赖数据。

### 入树与继续计算

根是最后一个已经提交、仍待完成其模型状态计算的 token，路径分数为 1。后缀查询可立即从根提出续写。每个活跃节点沿循环深度继续推进；Ouro 在第 1、2 轮读出，第 4 轮验证，Huginn 在第 4、8 轮读出，第 32 轮验证。

对候选 v，计算 `S(v)=S(parent)×e(parent→v)`，严格大于 τ 才新建节点。同一父节点下同一 token 只占一个节点。新建模型候选后立即以其候选上下文再查后缀，因此两种来源可以交替延伸；猜测 token 可以作为查询上下文，但没有验证就不会写入历史。

例如 τ=.03：

```text
已提交根，S=1
└─ A：模型分数 .60，S=.60          → 入树
   └─ B：后缀分数 .40，S=.24      → 入树
      └─ C：后缀分数 .10，S=.024  → 不入树
```

这只是如何分配提前计算的示例，不表示 ABC 的真实接受概率是 .024。后缀频次和模型 softmax 的含义不同，raw 未把它们校准成同一种事件概率。当前调度推进所有尚未完成的活跃节点，不按最高分逐个执行；分数主要控制入树、重评分和剪枝。每次后缀查询最多 64 个草稿 token，每请求树容量 1024；容量不足时跳过新增节点，不是每轮全局排序再保留最优 1024。64 也不是整棵树全局深度上限。

### 新读出如何改树

根的第二次读出若将 A 的分数从 .60 改成 .20，则 A 的 S=.20，B 的 S=.08。旧的 .60 被替换，不再额外乘一次 .20。若改成 .02，A 自身低于阈值，会连同 B 子树删除。若后缀再次提出已经存在的 A，只标记其也有后缀来源，不覆盖现有边分数或叠加奖励。

实现有两个需要准确描述的细节：

- 当前 top-8 外的后缀孩子在第一次读出时，及待重评孩子在第二次读出时，以 ABSENT=0 处理。这是截断候选的启发式，不表示真实 softmax 恰为零。
- 重评一个孩子会更新整棵后代子树的路径分数，但本次只检查该孩子自身是否低于 τ；若它没有被删，不立即逐个筛掉所有变低的后代。因此不能声称树内任何时刻所有节点都满足 S>τ。已验证节点不会被重评分删除。

### 全深度怎样决定输出

只有当前已验证前缀上的全深度 argmax 决定下一个 token。若它是 A，提交 A，删除其兄弟分支，继续复用 A 的已计算状态；已经确认的 A 边改为 1，剩余 B 的分数恢复为 .40，不再为已经证实的前缀打折。接受后立即更新本题历史并续查。若下一节点也完成全深度计算，可以连续提交多个 token。

若全深度选择了树中没有的 token，仍然输出这个 token，并从它继续下一步。高分候选不会绕过验证，低分漏掉正确候选主要造成提前计算机会损失。以上是算法规则；Ouro BF16 的实际输出分歧仍未定位，不能据此宣称当前实现与串行 AR 无条件逐词一致。

raw 无需离线标签、分箱、四表或 50 次支持门槛。仍有 τ、top-8、读出深度和节点预算等参数；已冻结 τ 见 [raw 配置](../results/loopfill-icml-20261103/raw-score-policy.json)。
