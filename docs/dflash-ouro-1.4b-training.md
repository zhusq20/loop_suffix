# Ouro-1.4B DFlash 训练（2026-11-12）

按用户指定，本轮选定 **163,597,568 个可训练参数**的窄 DFlash drafter，配置为
[`baselines/configs/dflash-ouro-1.4b-163.6m.json`](../baselines/configs/dflash-ouro-1.4b-163.6m.json)。
这是训练规模选择，不代表已证明最优的速度或接受率。

| 配置 | 数值 |
|---|---|
| Transformer 层数 | 5 |
| hidden / FFN | 1536 / 4096；目标hidden仍为2048 |
| attention / KV heads | 12 / 12，head_dim=128 |
| draft block | 16 |
| 目标特征 | 第四轮的物理层 1/6/11/16/21，展开索引 73/78/83/88/93 |
| 输入特征融合 | 10240→1536，15,728,640 参数 |
| embedding/输出投影 | 2048→1536及1536→2048，合计6,291,456参数 |
| 五层 Transformer | 141,574,400 参数 |
| 其余归一化 | 3,072 参数 |
| BF16 权重体积 | 约 312.0 MiB；不含优化器、激活和目标模型 |

Ouro-1.4B 和已有 Ouro-2.6B 的 hidden、FFN 和注意力头配置一致，但目标物理层数
为24/48。沿用原目标宽度会得到277.9M drafter，而1.4B目标的计算量更少，草稿成本
更容易影响加速。因此首轮采用已实现的宽度投影，保留五层和block16，降低drafter宽度。
目标模型、embedding和LM head均冻结；投影层包含在上述参数量中。

| 候选 | hidden / FFN | 参数量 | 本轮安排 |
|---|---|---|---|
| 小 | 1024 / 2816 | 78,918,912 | 原等待队列在启动前撤下 |
| 中 | 1536 / 4096 | 163,597,568 | 用户指定，已选择并排队 |
| 原目标宽度 | 2048 / 5632 | 277,898,496 | 原等待队列在启动前撤下 |

当前配置比原278M方案少41.1%参数，但不能据此推断同幅度的实际提速。
训练后必须结合平均接受长度、draft耗时和端到端速度判断。
278M的v1和78.9M的v2控制器均已停止，确认没有启动teacher或训练进程。

## 数据与训练

现有冻结 `dflash-train` 清单共50,000条：数学20,000、Nemotron代码10,000、
UltraChat15,000、CodeAlpaca5,000。Ouro-1.4B 尚无该清单的 teacher 输出，
所以先由本模型完整四轮、greedy生成，最多512新token、总长度上限3072。
逐请求落盘；生成完成后核对完整ID覆盖、模型身份和SHA256。

过滤输出不足32token的样本，取有效数据中最长32条做一次真实权重训练预检。
预检通过后独立初始化正式训练：6 epochs、seed=42、全局batch32、
单卡micro-batch4×梯度累积8、学习率6e-4、warmup4%、512 anchors、
loss decay gamma=7、BF16与FP32优化器主副本、FlexAttention。
每500步和最终保存可恢复检查点；正式更新数为 `6 × ceil(有效样本数 / 32)`。
训练结束后验证真实退出码、完整步数、有限loss/梯度/权重和最终检查点哈希。
