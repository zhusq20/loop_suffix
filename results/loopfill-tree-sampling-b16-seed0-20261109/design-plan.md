# LoopFill：候选树概率采样与动态计算规模计划

日期：2026-11-09。

状态：**正在实施。** 树采样、独立事件随机流、稳定 log 概率读出和聚合诊断已实现，正在验证与准备正式 B16 实验。本文不改写已完成的消融或上限诊断结果。

执行范围更新（用户于2026-11-09明确要求不跑多种子）：本轮改为 **2模型×4臂×单种子0、单次计时=8个B16完整流**。各流仍为480题、最多1024新token；不执行下文建议的三个配对块，不宣称跨种子或重复计时稳定性。每模型四臂仍固定同卡、相同输入顺序。启动入口为 `scripts/loop_tree_sampling_suite.py`。

## 1. 目标与最小规则

目标是在保留正确路径提前计算收益的同时，减少无效分支的计算行数，提高实际 throughput。

第一版只引入一条选择规则：

> 从已经生成、合并后的候选树节点中，按路径分数有放回地抽 N 次；重复节点只保留一份，补齐必要祖先，超过 N 的路径跳过，不补满剩余预算。

固定 N=16，抽样次数也等于16；不新增温度、分数阈值、在线控制器或暂停/恢复策略。初始 suffix 按现有约定接入，后续选择才使用采样。

采样对象是**树节点**，不是词表 token，也不是 loop 深度。浅层模型仍在原定 loop 位置读出，每次提出 vocabulary Top-2；suffix 提案规则保持原配置。变化发生在这些候选合并之后的最终准入/保留步骤。

依据：[分数协调诊断](loopfill-score-headroom.md)显示，oracle-only 在三个模型共同输出子集上减少约47%—49%的 rows/token；Huginn 的 oracle 排序收益较大，两个 Ouro 的 γ 收益较小。这仅说明存在可研究的空间，不代表随机采样能取得 oracle 收益。

## 2. “没进 Top-k 就置零”究竟是什么

必须区分两个概念：

| 名称 | 含义 | 未入选是否意味着模型概率为0 |
| --- | --- | --- |
| vocabulary Top-k | 某父节点在某次浅层读出中，用于新增提案的 k 个 token | 否 |
| 树预算 Top-N | 合并候选后，最多保留 N 个草稿节点 | 否；表示不分配或不继续保留计算状态 |

当前 `_top_probs` 已经计算了整个词表的 FP32 softmax，然后返回 Top-k。若 suffix 已提出 token y，即使 y 不在 Top-k，仍可直接取得：

\[
q(y)=\frac{\exp z_y}{\sum_{w\in V}\exp z_w}.
\]

例如词表概率为 A=0.50、B=0.30、C=0.10、D=0.07、E=0.03，Top-2 只返回 A/B；已有候选 C 的读出概率仍为0.10。补取它不需要新增模型 forward 或读出轮次，但 gather、数据搬运和主机处理的额外成本必须计入吞吐。

现有实现有两种评分方式：

- **旧置零规则**：在 `model_candidates` 的适用重评分分支内，已有孩子未进入当前 Top-k 时，在 `existing_child_probs=False` 下将分数置0。这是人为的排序抑制规则，不是模型真实给出的零概率。
- **补取概率规则**：`existing_child_probs=True` 时，从同一份全词表 softmax 补取已有孩子概率；额外返回的 token ID 仅用于评分，不作为新增提案，不扩大 Top-k。

旧置零规则不一定是性能上的错误，也可能有抑制弱分支的价值，必须保留为实验对照。尤其需要注意：当前 `positive_only=False` 的确定性 Top-N 仍可能选入零分节点，所以旧置零**并不等于已经严格剪掉该分支**。改用分数比例采样后，只要存在正分候选，零权重节点不会被直接抽到；这会改变置零规则的实际效果。

对尚未在该父节点、该位置取得模型读出的候选，保留其合法的 suffix 分数或原有评分来源，明确“当前未取得模型评分”；不能凭空填成模型概率0。补取的概率是当前浅层读出的概率，不是全深度接受概率。不同深度的模型分数与 suffix 分数也不是已校准的同一种概率。

因此，本计划将**评分方式**与**选择方式**分开对照，不预设补取概率或随机采样一定更好。

## 3. 采样公式

### 3.1 路径分数与采样权重

设当前根为 r，候选集合 C 不包含 r。根始终保留，不占草稿预算。节点 v 的边分数为 e(v)，采用当前评分规则，路径分数为：

\[
s(r)=1,\qquad s(v)=s(\operatorname{parent}(v))e(v).
\]

本轮隔离实验统一固定 suffix 系数 c=1，关闭 online 更新；这与历史 online 母配置不同，因此各对照必须按新协议实测，不直接复用历史计时。

对有效分数归一化：

\[
\pi(v)=\frac{s(v)}{\sum_{u\in C}s(u)}
=\operatorname{softmax}_{v\in C}(\log s(v)).
\]

温度固定为1，不再对0到1之间的分数直接做一次 `softmax(s)`。π 是抽取候选节点的分布，不是最终节点入选概率，也不是节点正确概率；祖先补齐和预算检查会进一步改变入选分布。

实现应在 log 域累加路径分数，避免长路径乘积下溢。若边概率自身发生浮点下溢，应从已有 logits 获取稳定的 log-softmax 值，不用任意 epsilon 将“未知概率”伪装成一个很小的概率。

边界情况：

- C 为空：只保留根。
- 存在正权重：合法零权重对应 log 分数负无穷，不参与直接抽取。
- 所有有效权重均为0：回退当前确定性 Top-N，记录回退次数；不静默改用均匀采样。
- 缺失、NaN、负分数：作为评分/接口问题校验失败，不混同于合法零分。

### 3.2 有放回抽取

令抽样次数 K=N=16，在本次选择事件中固定 π：

\[
v_1,\ldots,v_K\overset{\mathrm{iid}}{\sim}\operatorname{Categorical}(\pi).
\]

允许重复抽到已经抽过或已由祖先补齐加入的节点。重复不额外分配节点，不重抽补名额，也不重复计算。

不能改成“无放回采满16个”：那主要改变候选组成，并不能实现此处依赖重复、去重而缩小规模的规则。

### 3.3 祖先闭包与预算

P(v) 表示从当前根 r 到 v 的路径，包含 r 和 v。初始化 A₀={r}，依次处理每个抽样结果：

\[
A_j=
\begin{cases}
A_{j-1}\cup P(v_j), & |(A_{j-1}\cup P(v_j))\setminus\{r\}|\le N,\\
A_{j-1}, & \text{否则。}
\end{cases}
\]

最终实际草稿规模为：

\[
N_{\mathrm{actual}}=|A_K\setminus\{r\}|\le16.
\]

预算不够时跳过整条新增路径，不保留缺少父节点的孩子，不截取部分路径，不在结束后用确定性 Top-N 补满。

保留下来的已有节点复用状态与循环进度，新节点从零进度分配，未保留分支按现有回收逻辑删除。物理 KV 容量仍预留 N+1（含根），无需每个 tick 重新分配大块显存。

实际每次推进的集合为：

\[
L_t=\{v\in A_K: \operatorname{step}(v)<T\}.
\]

已完成但尚未确认的节点仍计入草稿容量，但不再贡献推进行数。树节点数、未完成节点数和实际执行行数应分别记录。

### 3.4 小例子

设 N=K=4，仅为演示：

```text
r
├── a
│   └── a1
└── b
    └── b1
```

若抽到 `[a, a1, a, a1]`，最终为 `{r,a,a1}`，只保留2个草稿节点。

若抽到 b1，需要把 b 和 b1 一起加入。预算检查针对补齐祖先后的集合，而不是只检查抽到几个不同节点。

## 4. 初始 suffix 与选择时机

“初始必取”仅指一次请求刚开始、尚无草稿浅层读出的首次边界。在 N16、根部 Q4 下，suffix 返回的最多4个候选全部接入；未命中则没有这些节点。首 token 已结束请求时沿用现有提前结束逻辑。

初始接入不等于永久保护。后续候选合并时，仍存活的初始 suffix 节点也进入统一选择。

当前 `boundary` 在子节点 suffix 查询前后各有一次 `choose`。**不能直接把两次调用都替换成独立随机采样**，否则每个边界会重复筛除候选，也会混入查询调度的额外变化。

第一版的接入位置明确为：

1. 按现有规则处理模型读出、已有孩子重评分以及根部 suffix 查询。
2. 查询前的确定性 Top-N 暂时保持，用它决定哪些新模型孩子触发 Q4 续查。
3. 完成子节点 suffix 提案后，在最终选择处执行一次上述随机采样；初始边界例外，仍确定性保留。
4. 回收未选分支、分配新节点，然后正常推进与全深度验证。

因而第一版采样的是“现有前置选择和续查流程产生的最终候选池”，并非保存无限历史候选的全局池。前置确定性筛选的限制需写入报告。本版也不额外随机门控 vocabulary Top-k，不改变 suffix 查询上限，不引入 CPU 候选仓库或暂停/恢复调度。

选择仅发生在已有 proposal/根推进边界，不在没有新证据的每个 tick 额外重采样。单个边界只消耗一次采样事件编号，重评分函数不得隐式推进随机数生成器。

## 5. 实现任务

以下均为待实现事项：

- 在配置中新增选择策略开关，区分现有确定性 Top-N 与有放回树采样；旧默认保持可复现。
- 复用已有孩子概率提取接口，将评分与选择分开，允许在同一份候选分数上比较两种选择策略。
- 实现 log 域权重、固定 N 次抽取、去重、祖先闭包和预算跳过。
- 在 `boundary` 的最终选择位置接入一次采样，显式识别初始边界；前置选择保持确定性。
- 为草稿选择设置独立 RNG，不改变目标生成随机数或模型初始化随机数。以运行种子、模型、全局唯一请求ID、请求内选择事件编号确定随机流。
- 候选顺序按逻辑 token 路径固定，不能依赖物理槽号、集合迭代次序、GPU 编号或跨请求调度次序。
- 在诊断计数中记录抽样、去重、祖先补齐、超预算跳过、全零回退、节点释放与重建。
- 恢复执行时保存/重建每请求选择事件编号；相同轨迹与种子应得到相同选择。BF16输出差异仍须单列。

不预设新的字段名已经可用，也不将既有 `positive_only` 当作本采样策略的实现。

## 6. 正确性与边界检查

实现完成后至少覆盖：

- 根永远保留；最终集合祖先闭合；草稿节点数不超过N；执行行数不超过N+1。
- 重复抽样不增加节点；抽满K次后不补齐、不重抽；祖先闭包超预算时完整跳过。
- 初始 suffix 全保留；之后可以参与采样；同一选择边界不重复随机筛选。
- 空候选、合法全零、无效分数分别按约定处理；log 域避免长路径下溢。
- 补取已有孩子概率与完整 softmax 一致，新增模型提案仍只有原定 Top-k。
- 选中已有节点保留进度，释放后重用槽位不残留旧祖先/KV引用；根推进后路径和位置正确。
- 相同种子和事件顺序可复现，草稿随机流独立于目标生成。
- 小型确定性模型上检查与全深度 greedy 输出一致；真实 BF16 模型单独审计树形数值差异，不能承诺逐 token 完全一致。
- 单请求、continuous batching 和 packed 执行均验证；正式计时不携带完整观察器 trace。

## 7. 实验矩阵：将置零与随机选择分开

首轮四臂构成2×2对照，其他参数一致：

| 变体 | 未进当前读出Top-k的已有孩子 | 最终选择策略 |
| --- | --- | --- |
| A：旧评分＋Top-N | 沿用当前适用分支的置零规则 | 确定性Top-N，允许零分填入 |
| B：补概率＋Top-N | 补取已有孩子实际读出概率 | 确定性Top-N |
| C：旧评分＋采样 | 沿用旧置零规则 | 本文有放回采样 |
| D：补概率＋采样 | 补取已有孩子实际读出概率 | 本文有放回采样 |

关键比较：

- B−A：补取概率本身的净影响。
- D−B：同样补概率评分下，随机准入的净影响。
- C−A：保留旧置零评分时，选择策略变化的净影响。
- D−C：随机准入下，是否应该保留旧置零规则。

若收益只出现在C，应检查是否主要来自零分排除，而非随机性；可再补“旧评分＋`positive_only`＋确定性Top-N”定位。若只是平均规模变小，可再补同评分的固定N8，判断是否值得使用动态策略。两项属于结果驱动的后续对照，不预先扩展成大矩阵。

建议执行范围：

- 先在 Huginn-3.5B 与 Ouro-2.6B 的 B16 测吞吐，固定双读出、Top-2、根部Q4、孩子Q(4,4)、N16、c=1、greedy、BF16、Graph-off、无执行行填充。
- 正式吞吐沿用完整 SpecBench 480题、最多1024新token、逐流冷启动和完成请求历史，模型加载/预热/网络上传不计时。计时口径与[四组消融协议](loopfill-paper-experiments.md)一致，但新配置重新计时。
- 建议3个配对运行块，四臂在同卡、相同输入顺序下轮换运行；采样臂在三个块使用预先固定的草稿种子0/1/2。对应2模型×4臂×3块=24个完整流，属于未来执行建议，不表示已启动。
- 上述设计同时覆盖运行波动和草稿种子变化，不将两类方差误称为已分离；若需分离，另做同种子重复。
- B16确有净收益后，再补B1延迟检查。首轮不扩展预算、温度、抽样次数、Top-k或Q的联合扫描。
- SpecBench已经参与过参数设计，本轮只能称同分布机制/性能验证，不称独立held-out确认；后续泛化结论需独立数据。

## 8. 指标、解释与完成标准

主指标：正式 B16 端到端输出吞吐；B1补充时报告 decode 延迟。不能把诊断 trace 的耗时当作吞吐。

辅助指标：γ、loop steps/token、rows/token、readout rows/token、suffix 查询次数、选择/采样耗时、错误路径丢弃行数、预算淘汰行数及已算过节点重建次数。

动态规模需同时报告：

- 实际保留草稿数、未完成节点数、每次实际执行行数的分布。
- K次抽样中不同被抽节点数、重复率、祖先补齐后的数量、最终保留数。
- 超预算路径跳过次数、全零回退次数、零分候选的保留/计算情况。
- 保留路径深度分布，检查路径乘积分数是否过度偏向浅层，尤其是Huginn。
- 输出长度、停止原因、输出差异；同输出子集仅作条件诊断，不能替代全体结果或任务质量检查。

若 rows/token 下降但 throughput 也下降，说明失去提前计算、重建或采样开销抵消了收益；不能只凭树更小或γ更高宣布成功。GPU保留容量未变时，也不把计算行减少写成显存占用下降。

若采样收益只在少数种子出现、需要大量全零回退，或者依赖明显的输出变化，结果不足以支持稳定加速结论。四臂应完整报告，不只选最快一次。

计划实施的完成标准是：代码与边界测试通过、每臂协议/输入/源码/种子可追溯、所有计数与日志齐全、正式吞吐和代价分解都已报告。最终策略是否值得采用，由净吞吐和延迟结果决定，不要求实验一定得到正收益。
