# Loop投机解码第一步：浅层备选分支（免训练，2026-10-30）

用户2026-10-30授权，在GPU 2、3直接运行；只做推理，不训练。依据：[拒绝后复用审计](../loop-spec-reuse-20261030/protocol.md)前约50题的事后统计显示，WaveFront（WFD）的循环调用中约35%（Ouro）／45%（Huginn）花在核对出错后的重开上；出错时正确词是浅层第2候选的比例约52%／54%。LoopSpec（2609.17184）的第二候选在更深一层出现分歧时才开；本方法在浅层起草时就按置信度开备选分支。

## 方法

主链与WFD相同。主链某词到达起草深度d时：取浅层第1候选作为下一位置的草稿；若第1候选概率 `p1 < τ`，再以第2候选在同一位置开一条备选分支。备选分支在同一批循环调用里推进，并沿自己的第1候选继续起草，不再分叉。该位置被核对时：主草稿正确则丢弃备选；主草稿错误且全深度结果等于备选首词，则备选分支整支接替主链被冲掉的部分；否则按WFD从改正的词重开。

KV：备选分支在分叉位置之前读主缓存，之后读自己的小缓冲；接替时把缓冲拷入主缓存。每个提交的词都是全深度argmax，精确算术下与贪心逐词生成相同。

## 设置

模型、深度与WFD论文相同：Ouro-2.6B（T=4，d=1）、Huginn-0125（T=32，d=4，按位置播种随机初值），贪心，不开KV共享。τ∈{0（关闭备选，等同WFD）, 0.5, 0.8, 2（总是开）}。Spec-Bench六类，每类按question_id均匀取题，最多生成256词。

1. **fp32核对**：每类1题，检查各τ与逐词生成逐词一致。
2. **bf16测速**：每类10题（共60题）。每题依次跑逐词生成、WFD原版、各τ，先各做4词预热，用同一进程交替计时。

## 指标

每词循环调用数（与硬件无关，主指标）、相对逐词生成的吞吐倍数、相对WFD的倍数、平均每次调用的行数、备选开启次数与接替次数；τ=0与WFD原版逐词与调用数一致性；fp32与逐词生成一致性。

## 已知限制

GPU 2、3同时运行hop-matched训练，墙钟测速受争用影响；同题交替计时可部分抵消，正式墙钟数字需在空闲卡上复测。Huginn备选分支的coda按分支分组调用，多出的coda调用次数单列。只计调度，不含CUDA graph等优化。
